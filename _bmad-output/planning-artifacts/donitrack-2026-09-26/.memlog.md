- (decision) Target use case: Diaspora sending parcels to family in Mali/West Africa with trust, transparency, and choice of carrier
- (decision) Carrier vehicle capacity: Carriers propose available containers or trucks with departure schedule
- (decision) Handover options: Drop-off at designated point/schedule, phone coordination, or home pickup within configured km/geo radius
- (decision) Preconfigured package catalog: Configurable items by carrier (e.g. 50/100kg travel bags, 100/200L barrels, various cartons) with clear pricing, dimensions, and photos
- (decision) Dynamic labeling with transparent indirection: Package label has persistent code linking dynamically to container/truck/trip; carrier can reassign transport without relabeling physical parcel
- (decision) Granular milestone timeline: Warehouse received, loading started (truck/container/plane), transit progress (1/4, 1/2, 3/4 distance), arrived at destination, delivered
- (decision) Dual tracking access: Public guest tracking by code + Authenticated customer space with history by carrier, search, filter, and sorting
- (decision) Direct communication channels: Phone call, SMS, and in-app customer-carrier messaging
- (decision) Carrier backoffice: Manage trips/departures, vehicle capacity, cargo manifests grouping customer parcels, status updates
- (decision) Backend architecture: .NET 9 Modular Monolith based on Architecting ASP.NET Core Applications 3E (C20 pattern), Minimal APIs, applications/modules/shared
- (decision) Frontend & UX: Next.js 14, React 18, MUI v6, TanStack Query, mobile-first, Design System inspired by Weft branding (#273349, #5AFBC4, Rubik/Kodchasan)
- (event) PRD, Architecture, and Epics updated to reflect complete user specifications: carrier capacity, preconfigured package catalog, dynamic labeling indirection, granular milestones, direct communication, C20 modular architecture, and Weft branding theme.
